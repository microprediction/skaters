# skaters

Rust port of the [skaters](https://github.com/microprediction/skaters) online
distributional forecasting core. Every forecaster is a struct with
`step(&mut self, y: f64) -> Vec<Dist>`, and all state is plain data. That is
a product contract: a skater can be checkpointed to JSON and restored, here or
in another port.

## State

`State::state_to_json` writes a skater's state in the canonical layout of
[docs/STATE.md](../docs/STATE.md), exactly as Python's `state_to_json` writes
it, and `State::load_state` reads it into a skater built from the same
factory. A Python state of `None` (before the first observation) is `null`
here, and a fresh Rust skater writes `null`. So a checkpoint moves between
Python and Rust in both directions:

```rust
use skaters::{laplace, State};

let mut f = laplace(1);
for y in history { f.step(y); }
let text = serde_json::to_string(&f.state_to_json()).unwrap();   // Python reads this
let mut g = laplace(1);
g.load_state(&serde_json::from_str(&text).unwrap()).unwrap();      // or a Python checkpoint
```

The serde derives remain as Rust's native format (configuration plus state),
which older skaters-fast checkpoints use; they still load.

## Parity discipline

No module ships without passing the parity vectors. `parity/vectors.json` is
generated by the Python reference and embeds the input series, so both sides
run on identical floats. The gate replays every implemented scenario and
compares seven probes per step and horizon (mean, std, logpdf at 0.3, cdf at
0.3, quantiles 0.1 and 0.9, CRPS at 0.3) at atol = rtol = 1e-6:

```
cargo test --release
# parity: 120 scenarios, 209552 values checked
```

At the burn-in step of every scenario the gate writes the canonical state to
JSON text, loads it into a freshly built twin, and requires the twin to match
the original bit for bit for the rest of the series. `tests/resume.rs` runs
the cross-language resume on `parity/resume_vectors.json`
(`parity/gen_resume.py`): every scenario resumes Python's checkpoints at
t = 60, 250 and 530 and matches the next 20 steps to 1e-6, and writes its own
checkpoints to `parity/resume_rust.json` for `parity/check_resume.py`.
`tests/test_rust_resume.py` runs both directions, granger included.

Coverage is the full library: every transform and leaf at k=1 and k=3, the
ensembles (precision-weighted, bayesian, terminal-leaf), multiscale, sticky
(on the repeat-heavy series), the GPD tail splice, the full `laplace`
composition (`pol_laplace`, `pol_laplace_k3`), the adaptive search
(`search_default`, `dantzig`), the wave-2 wrappers (`homogenize` in every
couple mode, `residual_transform` m0/m1/m2, the terminal ensemble's adaptive
temperature), the spec build path and spec JSON strings,
the periodicity detector (ranked lag/acf block), and the covariance
estimators (running, EMA, Ledoit-Wolf blocks). Nothing is skipped.

Two details matter for agreement beyond ordinary care with operation order.
Sums that Python computes with the built-in `sum()` use a Neumaier-compensated
`fsum` (CPython 3.12+ compensates float sums; naive accumulation diverges the
prune tie-breaks). And `Dist::prune` reproduces the ulp-tolerant closest-pair
merge exactly, which exists precisely to keep platforms in agreement.

## Portable math

All transcendentals (exp, log, log1p, expm1, pow, erf, erfc) route through the
pure-Rust `libm` crate, never the system libm. Portable math means identical
bits on every platform including wasm32. Parity versus Python remains the
1e-6 vector gate above; within a platform family the Rust core itself is
bit-deterministic.

## Usage

```rust
use skaters::laplace;

let mut f = laplace(1);
for y in observations {
    let dists = f.step(y);
    println!("{} {}", dists[0].mean(), dists[0].std());
}
```

`laplace(k)` is the general forecaster: a likelihood-weighted ensemble over
the full candidate population with a CRPS terminal leaf, the lattice
projection for repeating values, GPD tail splicing, and PIT/z calibration
state (`Parade::pit`, `Parade::z`). At k > 1 it runs multi-scale over
decimated clocks. Building blocks (`conjugate`, transforms, leaves,
ensembles) are exported for composition. `conjugate` keeps Gaussian mixtures
throughout; `conjugate_f` wraps any `Forecaster`, so a transform's inverse sees
the full predictive (tail-spliced, or a `PushforwardDist` from `exact`
inverses, `log_transform` and `flesaker`).

## Python backend (skaters-fast)

`rust/python/` is `skaters-fast`, an opt-in PyO3 skin that lets Python run the
identical `laplace` model at about 20x the per-step rate of the pure Python
reference with the same bits on every platform. Build it into a venv with
`maturin develop --release -m rust/python/Cargo.toml`. See
[rust/python/README.md](python/README.md).

## Benchmark

`cargo run --release --bin bench` times `laplace(1)` over 5000 ticks (the
parity series, tiled). On an Apple M-series laptop:

```
laplace(1) step:        14.1 us/tick
laplace(1) step + mean: 300.5 us/tick
```

The second line adds one `mean()` read per tick. After the tail splice
activates (tick 500) that read evaluates a 65-node numeric quantile grid on
the spliced predictive, which is why probing moments costs far more than
stepping. Cheap queries (cdf, logpdf, a single quantile) do not pay that
cost.
